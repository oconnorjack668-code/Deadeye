## One direction, no alternatives

The brief fixes the direction (today's look, polished), so there are no rival directions. The one design choice that could go two ways is the age question, which is in "For safety-reviewer" below.

**What is the same everywhere.** One slim header (logo, "Deadeye setup", red "Aim is earned" at 12 px, and a 44 px Settings button; a close button when editing). No search, profile pill or tab bar. A full-width progress bar with "Step 1 of 3" and the step name. Form in the polish auth card (`rounded-2xl border border-zinc-800 bg-zinc-900/70 p-4`) with an icon tile (`bg-zinc-800 text-orange-300 ring-1 ring-inset ring-white/10`; icons kept: user, activity, target). A **sticky footer** (`border-t border-zinc-800 bg-zinc-950/95 px-4 pb-5 pt-3`): Back (outline, steps 2 and 3) beside a full-width orange Next or Finish (`size="lg"`, 52 px). One selection language: chosen = orange outline plus tint plus a check or filled dot (`border-orange-500 bg-orange-600/10`); the solid orange fill is only the next action. Control borders `border-zinc-500/70` (3.3:1). Labels sentence case 14 px, not 12 px capitals.

## Build note (for D4)

- `onboarding/page.tsx`: slim header and sticky footer (`pb-32` on the content); delete the `Card` wrapper per step in favour of one card; units default `'metric'` (the saved value still wins); scroll to top and move focus to the step title when the step changes; `aria-pressed` on chips, `role="radiogroup"` on the level rows and hand; Back, Next and Finish `type="button"`.
- Hide the app chrome on `/onboarding`: `Navbar.tsx` and `BottomNav.tsx` (client components, `usePathname()`; `QuickLog` already hides there). Simplest is a setup layout or a `pathname.startsWith('/onboarding')` return in both. The Settings button in the header is the only way out, and where sign out and delete account live.
- Chips: move the three option lists to `src/lib/focusAreas.ts` as `{ value, label }` (the stored string is what `recommend.ts` and `focus/signals.ts` key on, so **do not rename the stored values**, only the labels) and use the same label function on `profile/page.tsx`. This avoids a migration for "Defence".
- `ui/Alert.tsx`: body `text-xs` to `text-sm` (shared, small).
- Age: see below; touches `AgeBracket` in `types.ts`, `validation.ts`, `parentApproval.ts` (`allowedAgeBrackets`).
- Reduced motion: nothing moves except the existing 150 ms colour change on chips and `active:scale-[0.98]` on buttons; add `motion-reduce:transition-none`. No entrance animation.

## For safety-reviewer (age questions are here for safety)

1. **Dropping the second age question.** Sign-up gives `age_checks.is_16_plus`; the bracket still carries safety: `isAdultBracket` in `reminders.ts` (streak warning default), `entryRoute` in `competition.ts` (adult versus ask a parent), `isAdultCoach`, and the minor test in `coach/setup/page.tsx`. So a 16-or-older player must still say 16 or 17 versus 18 or older; an under-16 need not be asked.
   - **A (recommended).** New stored values `13-15`, `16-17`, `18+`: migration with a backfill (`13` and `14-17` with `is_16_plus` false become `13-15`; `14-17` with true becomes `16-17`; `18-22`, `23-30`, `30+` become `18+`), a new CHECK, and the four code places above. Under-16 saves `13-15` without asking.
   - **B (no migration, first release).** Under-16 saves `13`, "16 or 17" saves `14-17`, "18 or older" saves `18-22`. All four code places keep working; Profile and the AI coach would show "18-22" for an older adult. Not recommended beyond a first release.
2. **Equal weight, no nudge.** "18 or older" is now one tap, not a dropdown pick, and it opens competition entry without a parent. It is self-declared, as today. The two choices are the same size and look, nothing preselected. Please confirm that is acceptable, or ask for a harder step.
3. The hint "players under 18 get extra protections, like a parent saying yes to competition entries" is true today (`ask-parent` and `under16` routes); check the wording.
4. "Shown on leaderboards" hint on the name field, for under-18s: confirm.
5. Hiding the Navbar removes Settings as a visible path. It stays one tap in the header. Confirm that is enough for an under-18 mid-setup.
6. Defaults saved unchosen (position `G`, hand right, level `intermediate`, goals, focus, strength): unchanged from today, but they are the same kind of default the height fix removed. Say if any should start empty.
