# Deadeye design rules

How Deadeye looks, written down so every agent builds new screens the same way. Read it before
adding or changing UI. It describes the app as it is (taken from the code, 23 Oct 2026), so
follow the existing primitives before inventing new ones.

## The look

Dark by default with a light theme (below), quiet zinc surfaces, one orange for what to do next, heavy type for the numbers that
matter. A training tool, not a SaaS landing page.

## Building blocks

Use `src/components/ui/` first: `Button`, `Card`, `Badge`, `Alert`, `Input`, `Select`.

| Thing | Use |
| --- | --- |
| Page background | `--background` (#09090b, zinc-950). Set in `globals.css`. |
| Card | `rounded-2xl border border-zinc-800 bg-zinc-900/70 p-4` (or `<Card>`) |
| Inner row, list item, small tile | `rounded-xl`, `bg-zinc-950/60` or `bg-zinc-900`, `p-3` |
| Pills, avatars, dots | `rounded-full` |
| Primary button | `<Button>` (orange-600, `rounded-xl`, `h-11`, the 44px touch target) |
| Secondary action | `<Button variant="secondary">` or `outline`; plain text links for the least important |
| Font | Geist sans (body), Geist mono only for code-like values |
| Icons | `lucide-react` only, `h-4 w-4` inline or `h-5 w-5` in buttons |

## Type

One scale, so a new screen never picks a size by eye (Tailwind names, px):
12 `text-xs` · 14 `text-sm` · 16 `text-base` · 20 `text-xl` · 24 `text-2xl` · 32 `text-3xl`
· 48 `text-5xl`. Line height 1.5 for anything read (Tailwind's default for these sizes).

- **12px is the floor**, and only for labels: section labels, badges, chart captions. No
  `text-[10px]`/`text-[11px]` (removed 1 Nov 2026). A sentence someone reads is 14px or more.
- Page title: `text-xl md:text-3xl font-black tracking-tight text-white`.
- Big numbers (makes, streak, XP): `font-black tabular-nums`.
- Section label: `text-xs font-semibold uppercase tracking-wider text-zinc-400`.
- Body: `text-sm text-zinc-300`. Secondary: `text-sm text-zinc-400`; `text-zinc-500` for the
  quietest text (hints, timestamps). `text-zinc-600` is never text: it is under 3:1.
- No serif fonts. No gradient text.

## Contrast

Every text colour passes WCAG 2.2 AA, 4.5:1 (3:1 for 24px or 18.5px bold and up), in both
themes; borders a control needs to be found by, 3:1. Measured 1 Nov 2026, and fixed at the
palette in `globals.css` rather than screen by screen: `zinc-500` is `#8b8b94` (was 3.8:1 on a
card, now 5.5:1), and `orange-600` and `emerald-600` take their 700 shade so white text on a
primary button is 5.2:1 (was 3.6:1). Buttons brighten on hover (`hover:brightness-110`)
rather than switching to a lighter shade that white text fails on.

## Light and dark

The app opens on the phone's own setting; Settings > Appearance pins Light or Dark, kept on the
device (`src/lib/theme.ts`). A script in the root layout sets `<html data-theme>` before the
first paint, so there is no flash.

Components keep writing the dark classes they always have (`bg-zinc-900`, `text-white`,
`text-orange-400`). The light theme re-points Tailwind's colour variables in
`src/app/theme.css`, generated by `node scripts/build-theme-css.mjs`: the zinc scale turns
over (page `zinc-100`, cards white, text near-black) and the light accent shades used for text
become their 700 shade. So:

- Write for dark, as before. Check the screen in light too.
- Text on a solid accent button (`bg-orange-600` and friends) stays white automatically, and
  dark text on a bright one (`bg-amber-500`) stays dark.
- Anything on `bg-black` - video, the tracker's overlay, replays - stays dark in light, since
  it sits on footage. Wrap other must-stay-dark areas in `data-theme="dark"`.
- Something that must be white in both (a QR code's background) uses `bg-[#fff]`.

## Colour means something

Keep each colour to its job, so a player can read a screen at a glance from the three-point line.

| Colour | Means | Examples |
| --- | --- | --- |
| Orange (`orange-500/600`, text `orange-300/400`) | The action to take, the brand | Primary buttons, "Today" card, focus rings |
| Red (`red-400`) | Brand mark and misses, errors | "Aim is earned" label, a missed shot, `Alert` error |
| Emerald (`emerald-400/600`) | Made, saved, done | A make, "Saved", success badges |
| Amber (`amber-400/500`) | Needs attention soon | Streak at risk, "check this one", heavy workload |
| Cyan (`cyan-400`) | Neutral information | Workload note icon |
| Zinc | Everything else | Surfaces, borders, body text |

Roughly 70% zinc, 20% supporting colour, 10% orange. If a screen looks orange all over, it has
lost its one call to action.

## Spacing

- Mobile first. Design at phone width, then add `sm:`/`md:`. No horizontal scroll.
- Inside a card: `p-4`; between rows `space-y-2` or `space-y-3`.
- Between cards in a page stack: **every card gets a gap below it.** On the dashboard each card
  owns `mb-4` (sections end with `mb-8`). A component dropped into that stack must carry its own
  `mb-4`; the "Pick your club" card did not, and sat flush on the box below (fixed 23 Oct). On a
  new page, prefer `space-y-4` on the parent so the gap cannot be forgotten.
- Touch targets at least 44px high (`h-11`) for anything tapped at a court.

## Motion

One curve, `var(--ease-deadeye)` (`cubic-bezier(0.2, 0, 0, 1)`), 150-300ms for interface changes.
Two rewards that show progress happening: `.deadeye-fill` fills a progress bar once when it
appears, and `<CountUp>` counts the % up once when a session is saved. Both stand still for
`prefers-reduced-motion`. Not more celebrations: the dashboard already has streaks, XP, badges
and levels, and piling on more is how reward features get muted.


Short and for a reason: a shot call (`.deadeye-flash`), a level-up (`.deadeye-pop`), press
feedback (`active:scale-[0.98]`). 150-300ms for interface transitions. No entrance animations on
content, no combined hover transforms. Respect `prefers-reduced-motion`.

One exception, chosen by the founder on 2 Nov 2026: the shot tracker's **streak flame**. At 3
makes in a row a flame stands beside the score, after the %, never over the numbers
(`StreakFlame`; founder, 11 Nov), and a pill reads "Heating up · 3" (orange) and from 5
"On fire · 5" (red). The MAKE/MISS call stands alone beside the rim, with "check this one" when the
tracker is unsure: the score and the streak are already on the overlay (founder, 13 Nov). Only
when there is no room beside the rim is it centred, with the count and "3 in a row" under it.
It lives only on the overlay over the video, which is the tracker's own broadcast-style
space and is also what a saved tracker video shows (`src/lib/video/overlayArt.ts` draws both).
Don't spread it to cards or the dashboard. The flame holds still for reduced motion.
The same overlay shows a **milestone banner** for 2.5s (`.deadeye-banner`): round numbers of
makes (10, 25, 50, 100...) and shots (50, 100, 200...), and a perfect 5/5 start
(`milestoneFor` in `overlayTimeline.ts`). Keep that list short; it is not for every shot.

## Avoid (the AI-slop list)

Adapted from the community Unslop UI skill, trimmed to what applies here.

- **Icons in coloured rounded squares** as decoration. One is deliberate: the tile in
  `PageHeader`, whose colour says which tab you are on (hoops orange, gym green, IQ blue, train
  orange to red), so keep it. About 30 older one-off tiles remain (the streak flame, tips, club
  cards and so on). Don't add new ones, and when you change a screen that has one, put the icon
  inline or drop it.
- **Emoji as UI.** Not in headings, cards or feature lists. Fine in user posts and in marketing
  captions.
- **Glassmorphism**: blur plus translucent card plus light border over a gradient. `Card` keeps a
  light `backdrop-blur-sm`; don't stack more blur on top.
- **Gradients everywhere.** One highlighted card per screen may use
  `bg-gradient-to-br from-orange-600/15 to-transparent` (the "Today" card pattern). Never on
  buttons or text.
- **Glowing coloured shadows.** Buttons keep their faint `shadow-*-950/20`; nothing stronger.
- **Cards inside cards.** Use type size, weight and colour for hierarchy, not another box.
- **Purple-to-blue, Inter, three identical cards in a row.** The generic SaaS look.
- **Claims the tracker can't back.** Copy says "counts your makes and misses", not "every"
  (see `docs/agent-os/marketing/2026-10-23-first-promo.md`).

## Before you ship a screen

- [ ] Checked at phone width (Playwright screenshot or a real phone)
- [ ] One obvious next action, in orange
- [ ] Colours match the table above
- [ ] Every card in a stack has a gap below it
- [ ] No new icon tiles (the `PageHeader` one is the exception), emoji, glow, gradient text or nested cards
- [ ] Works with `prefers-reduced-motion`
